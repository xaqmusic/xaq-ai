# Cell system audit, 2026-09 — appendix: the claim register

*Companion to [`cell_system_audit_2026-09.md`](cell_system_audit_2026-09.md). This is the
machine-checked half: one row per finding, with the anchors a reader (or
`tools/audit/claim_anchors.py`) can grep. Identifiers are allowed here; the report itself
keeps to prose. The register is a snapshot of the tree at the audit's commit; an anchor that
stops matching is a row whose evidence moved or was fixed, and the checker fails loudly.*

**Row shape.** id · claim (as the docs or configs state it) · what actually runs · anchors ·
measurement · status · severity · re-use context · **utility** (what the mechanism is good
for as it stands, where doctrine compliance is not required, or as a scaffold, baseline, or
instrument inside this project).

**Statuses** (added to the ledger's verdict vocabulary; each is scoped, never global):
`UNSUPPORTED` a doc claim with no live code path or measurement · `DEAD_PARAM` declared,
parsed, never read · `DROPPED_PARAM` a config key absent from the schema, silently dropped ·
`DEFAULT_TRAP` schema default ≠ effective default when omitted · `SCAFFOLD_UNNAMED` a
god's-eye dependency not declared as one · `HARNESS_INVALID` a measurement whose harness
violates the A/B protocol · `CONFIG_BROKEN` a shipped config that cannot run as described ·
`MISATTRIBUTED` a real result whose stated mechanism never ran · `RULE_VIOLATION(§x)` a
doctrine or `CLAUDE.md` rule · `OPEN` needs an operator verdict. Severity: **R** changes the
Cell report's reading · **D** changes a design decision · **H** hygiene.

Anchors are `path:pattern` in backticks (a literal substring, or `/regex/`).
